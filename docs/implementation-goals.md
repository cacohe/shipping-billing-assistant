# 实现目标与边界

## 1. 目标

完成一个可以运行和演示的航运智能账单助手，覆盖以下业务闭环：

```text
输入文件与已有账单
→ 多格式解析
→ 结构化信息抽取
→ 标准化与校验
→ 账单匹配
→ 操作及 AR/AP 判断
→ 合法 JSON 输出
```

同时提供 Streamlit 页面展示输入、处理阶段和最终结果。

## 2. 非目标

本项目不实现以下内容：

- 用户、角色和权限系统；
- 持久化文件中心或业务对象存储；
- 数据库持久化；
- 消息队列和后台任务集群；
- 多租户；
- ERP 自动写入；
- 独立人工审核工作台；
- 向量数据库或知识库平台；
- 多 Agent 协作框架；
- 模型训练或微调；
- OCR 模型本身；
- 生产级部署、监控和弹性扩容。

## 3. 实现顺序

### 阶段一：领域模型和契约

- 定义输入请求、统一文档、抽取结果、已有账单和最终输出模型；
- 固化最终 JSON Schema；
- 明确缺失字段、冲突和低置信度的处理规则。

### 阶段二：多格式解析

- 实现格式调度；
- 实现 EML 及附件递归；
- 实现 Excel 和 Word 解析；
- 实现可配置 OCR API 适配器；
- 对带文本层的 PDF 补充本地文本提取，避免 OCR 结构化结果丢失实际费用行；
- 输出统一文档模型。

### 阶段三：LangChain 抽取

- 建立结构化输出模型；
- 编写抽取提示词；
- 提取单据信息、交易双方和费用明细；
- 记录字段来源与置信度；
- 对无效结构进行一次不增加业务事实的修复；结构合法但费用为空且原始输入存在明确金额候选时，进行一次保守语义复核：已有唯一单据时只合并费用，空信封时只接受复核得到的唯一单据，多单据歧义时保留首次结果。

### 阶段四：领域规则

- 费用名称、币种和付款方式标准化；
- 金额、合计、费用级 OCR 易错字符、来源行重复项和来源级证据原文校验；
- 实现四级账单匹配；
- 实现 CREATE/UPDATE/NO_CHANGE/PENDING_REVIEW；
- 实现字段继承和 AR/AP 判断。

### 阶段五：输出和测试

- 按费用项目生成记录；
- 校验最终 JSON；
- 在单元测试中为 OCR 和 LLM 提供测试替身；
- 构造覆盖主要成功、失败和冲突场景的样例。

### 阶段六：Streamlit 演示

- 实现输入区域；
- 通过核心应用的阶段回调显示处理过程；
- 展示警告、错误和最终 JSON；
- 提供 JSON 下载。

## 4. 完成标准

- 支持约定的输入格式；
- EML 正文、邮件头和附件能够被解析；
- PDF/图片通过配置的 OCR 客户端处理；
- Excel/Word 表格可以转换为统一结构；
- 每个费用项目输出一条合法 JSON 记录；
- 费用名称、金额、币种和付款方式按要求处理；
- 能够区分四种操作类型；
- 更新时不会覆盖未明确变更字段；
- AR/AP 判断包含当前记账主体和交易方向；
- 确认来自同一来源行的重复、匹配冲突和低置信度结果进入待复核；无法精确定位的同值费用逐行保留并告警；
- 模型输出的费用及变更证据必须能通过唯一来源 ID 和文件名定位到原文，变更证据中的新值必须与候选字段一致；
- 单元测试能够在 Mock 外部依赖的情况下稳定运行；
- 集成测试能够验证实际解析器、外部适配器和完整业务流程；
- Streamlit 可以完整演示输入、处理过程和结果。

七牛云 Kodo 仅作为 OCR 接口的临时文件桥接：上传本地 PDF/图片、生成短期下载 URL，并在单次 OCR 调用结束后删除，不承担业务持久化。
